# Integritas = deterrence + audit trail, bukan pencegahan teknis

Sesi terkunci diimplementasikan sebagai web page (fullscreen + blok input + countdown pelanggaran), padahal semua proteksi client-side bisa di-bypass murid yang teknis — riset kami (Oktober 2026) menemukan tidak ada satu pun open-source lockdown *web* yang maintained: Safe Exam Browser dan Respondus LockDown Browser adalah client native. Kami memutuskan membangun web dengan sadar bahwa tujuannya bukan mencegah kecurangan 100%, melainkan menaikkan biaya kecurangan (deterrence) dan merekam bukti yang dapat dipertanggungjawabkan (audit trail): log Pelanggaran dengan alasan, riwayat semua percobaan, kunci ulang hanya via Izin Guru, dan Penilaian AI confidential yang tetap di bawah penilaian Guru. Alternatif yang ditolak: membangun kiosk/lockdown native (waktu 1 bulan tidak cukup, target pasar tidak punya instalasi klien) dan memperketat deteksi client-side lebih jauh (screenshot/mouse-tracking over-engineering + isu privasi, tanpa mengubah fakta bahwa bypass selalu mungkin).

Konsekuensi: jangan pernah "memperbaiki" proteksi dengan menambah deteksi client-side yang semakin agresif — penguatan sistem terletak pada ketajaman log, riwayat, dan alur Izin Guru. Path upgrade yang tercatat: token verifikasi server ala `X-SafeExamBrowser-RequestHash` bila ancaman naik.
